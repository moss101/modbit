# PX-179 task card — GUI regression suite on the fixture desktop, with a retained baseline

Decision Record: DR-PX-2026-10-26-018 (D1, D2). Evidence tier: iteration (an evaluation suite, its harness, a test fixture's state file and result bundles; no Core effect, store, policy, protocol or schema changes). Requirement REQ-PX-179; qualification QUAL-PX-179 / PX-E2E-179; prerequisites PX-178 and DOC-PX-017 COMPLETE.

## Audit (before)
Classification: DOCUMENTED-ONLY for the suite, as the row's audit says ("no GUI benchmark exists; the agent-engineering suite is six coding tasks"). What existed:
- `benchmarks/agent-engineering` (PX-020, PX-184): the harness that drives the real CLI and Core per trial, an immutable bundle, `axes.json` with cost per thousand tasks from recorded usage, `compare` with a per-axis gate (exit 3), a scripted OpenAI-compatible model server in the tests. Its axes were hard-wired to the four of PX-184, its approvals protocol denied every protected effect, and nothing set a computer actuator for a trial's Core.
- `services/modbit-actuator-fixture` (PX-069): the real actuator RPC over an in-memory desktop, driven through the real Core by `services/modbit-core/tests/px_computer.rs`; nothing read an application's state after a run from outside the Core.
- The GUI verifier row (PX-178, COMPLETE): `GuiEvidenceEvaluated` / `GuiOutcomeJudged` on a computer-use child's log, evidence declared by the parent in `agent.spawn`.
First missing link: no GUI task could be stated as a suite task — no desktop per task, no verifier that reads the GUI verifier row, no person to approve the per-call computer approvals (never allowlistable, PX-070), so a GUI trial could not run through the harness at all.

Real-application path (audited, not built here): the macOS helper `services/modbit-actuator-macos` exists in code and the Core launches it through `MODBIT_COMPUTER_ACTUATOR` or the signed manifest; its real-application tests (`qual_px_071_the_real_core_drives_a_real_application_through_the_real_helper`, `services/modbit-actuator-macos/tests/ax_fixture.rs`) are `#[ignore]`d and run only by `services/modbit-actuator-macos/scripts/ax-tests.sh` on a machine with Accessibility and Screen Recording granted. The graph holds PX-071 (the helper), PX-070, PX-072, PX-075 and PX-076 at NOT_STARTED. On this machine `target/debug/modbit-actuator-macos --check-permissions` (a read-only preflight, no prompt) answers `{"accessibility":true,"screen_recording":true,"secure_desktop":false}` for the process that runs cargo — the permissions are there — but this is the owner's working desktop, not a machine the owner has designated as the prepared machine, and QUAL-PX-179's real-application leg also needs a live model (the gateway key was refused with HTTP 401 on 2026-11-07). The real-application leg is therefore NOT PROVEN and NOT BUILT; see Known limits.

## Change
- `benchmarks/agent-engineering/src/suite.rs`: a task may carry `gui {desktop}` (a fixture desktop relative to the suite file, digested with the suite); the approvals protocol `approve-computer-inputs`. Validation refuses a GUI task without a `gui` verifier, a `gui` verifier on a non-GUI task, a desktop path outside the suite, and a GUI task under any other approvals protocol.
- `src/verifier.rs`: a `gui` check — the GUI verifier row read from the Core's records: a `GuiEvidenceEvaluated` at `COMPLETION`, on a child the task admitted (`SubagentAdmitted`), `PASS` for exactly the suite's predicate (a child declared with an easier predicate does not count); that child's `GuiOutcomeJudged` `VERIFIED` with evidence `PASS`; and element values of the fixture desktop after the run, read from the fixture actuator's own state file (`desktop_value`: an absent or ambiguous element is no value). A `gui` evidence that is not a completion-evidence predicate is refused.
- `src/axes.rs`: a suite may declare its own axes (`axes.names`; absent: the four of PX-184) and the per-task gate (`gate.per_task`): the report keeps each task's verified trials (`task_results`, checked by `verify_against`), and `compare` lists `regressed_tasks` (verified in every baseline trial, not in every current one — any one fails the gate whatever the axis rates) and `recovered_tasks`; a per-task baseline in which nothing verified is refused as a gate that cannot fail; reports of different axes are refused. The four-axis suite's digest and its retained baseline are unchanged (new fields are skipped when absent).
- `src/bin/competence_baseline.rs`: `--actuator <bin>` (default the sibling `modbit-actuator-fixture`); a GUI trial's CLI and Core get `MODBIT_COMPUTER_ACTUATOR` / `MODBIT_COMPUTER_ACTUATOR_ARGS` (`--desktop <task desktop> --state-out <file>`); under `approve-computer-inputs` a person thread answers the Core's approvals while `task run --wait` blocks — every `computer.*` input approved with the intent it was asked under, every other protected effect denied — and the counts are in the trial's notes; `desktop-state.json` is kept with the trial; the build digest includes the actuator; `axes.json` uses the suite's axes.
- `services/modbit-actuator-fixture`: `--state-out <file>` (the desktop's applications, windows and element values — never a secure value — written atomically at start and after every applied input) and `SetValue.window` (a dialog's button can change its parent window). Test fixture only; no Core or helper change.
- `suites/gui/`: 24 tasks (12 `gui_element`: set_value, press, a modal dialog confirmed and cancelled, two applications in one task; 12 `gui_input`: type, type then enter, key chords, coordinate clicks from a screenshot, one on an element with no accessible action) over seven Modbit-owned fixture desktops, a workspace fixture, and `scripted-model.json` (parent and child trajectories; `{{el:<name>}}` / `{{frame}}` resolved by the test's model server from what the agent was shown; the Core never sees it).
- `baselines/gui/`: the retained baseline (bundle, digest, `axes.json`, `summary.md`).
- `tests/gui_suite.rs` (5 tests) and README section; `Cargo.toml` registers `bench.gui_regression` for REQ-PX-179.

## Known limits
- **Real macOS applications: not built, not proven.** The row's scope includes "a small set of real macOS apps on a prepared machine" and QUAL-PX-179 asks for the real actuator with a live model there. Nothing in this change drives a real application: the harness passes fixture-only arguments (`--desktop`, `--state-out`) to the actuator, and there is no real-app task set. Reasons: (1) the macOS helper row PX-071 is NOT_STARTED (with PX-070, PX-072, PX-075, PX-076), its real-application tests are `#[ignore]`d and skipped on hosted runners; (2) no owner-designated prepared machine — this development machine does have Accessibility and Screen Recording granted to the process that runs cargo (`modbit-actuator-macos --check-permissions`), but it is the owner's working desktop and running GUI automation of real applications on it was not authorized; (3) the live-model leg needs a working gateway key, and the repository's key was refused with HTTP 401 on 2026-11-07. The row cannot pass REAL_TESTING until that leg is built and run.
- **Runtime defect found here, fixed in #186 (7143c7cb).** With a window node reported focused (the fixture's default, and a real key window's AXFocused through the helper), `computer.type` was refused TARGET_NOT_EDITABLE: `crates/computer/src/runtime/act.rs` took the first focused node of the tree as the keyboard focus, which is the window root. It now takes the deepest focused node, proven through the real Core by `qual_px_069_text_is_typed_into_the_focused_field_of_a_focused_window` (`services/modbit-core/tests/px_computer.rs`). The suite's desktops no longer set the window's `focused` to false; see "2026-11-08: workaround removed" below.
- The retained baseline is a scripted-model run: it measures the harness, the Core, the fixture actuator and the GUI verifier row end to end, not a model's competence; USD figures are catalog list prices for the model name given, not spend. The injected regression is model-side; no actuator regression is injected (QUAL allows either).
- Event logs and desktop states of the baseline run are not retained in the repository (the bundle keeps each log's digest and offsets; every test run regenerates them).
- The harness approves every `computer.*` input on the fixture desktop as the person; on a real machine those approvals are the person's.
- One trial per task; the per-task gate fails on any one regressed task, which suits a deterministic model. A live baseline below 100% would need several trials per task before the per-task gate is meaningful.
- Windows and Linux are not run locally; CI covers them.
